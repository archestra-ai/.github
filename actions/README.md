# Shared CI actions

Pin callers to a reviewed **full commit SHA** in `archestra-ai/.github/actions/<name>@<sha>`.
Dependabot checks workflows and `actions/*` weekly, grouping Actions updates with a seven-day cooldown.
Checkout the caller's source first (`lint-pr-title` needs none). All actions run inside the caller's job;
triggers, environments, permissions, service accounts and deployment checks stay there.

| Action | Required inputs | Optional inputs / outputs |
| --- | --- | --- |
| `google-auth` | `service_account`, `workload_identity_provider` | `setup_gcloud: 'true'`; `registry` also installs gcloud; `token_format: access_token` exposes `access_token`. Also outputs `project_id`, `credentials_file_path`. |
| `github-app-token` | `app-id`, `private-key` | `owner`, `repositories`, `permission-actions`, `permission-contents`, `permission-issues`, `permission-pull-requests`; outputs `token`. |
| `vercel-deploy` | `token`, `org-id`, `project-id` | `build-env`: JSON object of non-secret string values; outputs `deployment-url`. Always deploys production. |
| `release-images-publish` | `token`, `project`, `version`, `images-file` | `latest` (space-separated channels), `charts` (newline-separated `<chart>-<version>.tgz` files), `assets` (newline-separated release asset files, for a Terraform provider), `smoke`, `gate`, `app-id` and `private-key` (mint a new publisher token every 45 minutes, so the wait outlives the one-hour token), `publisher-repository`; outputs `run-url` and `run-id`. Sends a [release-publisher](https://github.com/archestra-ai/release-publisher) request for this run attempt, polls the publisher run (retrying failed polls) and fails when it fails. Attest every image and chart in the same job first. Release callers use the [`release-publish.yml`](../.github/workflows/release-publish.yml) reusable workflow, which runs this action and waits up to 360 minutes. `wait: 'false'` hands the request off instead (the step ends once the publisher run exists) and `request-file` keeps the request for `release-publish-verify`. |
| `release-finalize` | `operation` (`request`, `sweep`, `publish`), `token`, `project`, `release-workflow` | `requester`, `release-branches`, `tag-template`, `publisher-repository`; `request`: `request-id`, outputs `publish`, `run-id`, `version`, `tag-name`, `request-file`; `sweep`: `publisher-token`, `finalize-workflow`; `publish`: `tag-name`, `version`, `request-file`, `files`, `latest`, output `published`. Finishes a release that `release-publish.yml` handed off (`wait: false`): `request` reads the kept request from this repository's own release run, `sweep` dispatches the finalize workflow for each draft whose newest publisher run succeeded, and `publish` uploads the files (each the request names must match its sha256) and publishes the draft. Run `release-publish-verify` between `request` and `publish`. |
| `release-publish-verify` | `token`, `attestation-token`, `request-file`, `requester`, `signer-repository`, `signer-workflow` | `image-tag` (`{version}` or `v{version}`), `chart-repositories` (`<chart> oci://<repository>` lines), `publisher-repository`; outputs `run-url`, `version`. Run first in the workflow that finishes a handed-off release: the request's publisher run must be `publish.yml` on `main`, dispatched by `requester`, and successful; every public `<name>:<tag>` (a variant `<name>:<variant>`, at `<name>:<tag>-<variant>`) must hold the attested digest with a provenance attestation from `signer-workflow`; every chart must pull with the attested sha256. Needs `docker`, `gh` and `helm` (hosted Ubuntu runners have them). |
| `validate-vex` | none | `document` (default `vex/openvex.json`). Checks a project's OpenVEX document with the rules release-publish.yml applies when it attests it ([`attest-release-image/vex.py`](attest-release-image/vex.py): CVE or GHSA names, images as `pkg:oci/<image>`, one status per vulnerability, image and package, `not_affected` with a justification and an impact statement), so a bad statement fails the pull request instead of the release. Run it on pull requests after checking out the source. `vex.py` also edits (`set`) and renders (`render`) the document; see its docstring. |
| `attest-release-image` | `image` (a pullable reference pinned by digest; log in first), `subject-name` (the public name, no tag) | `platform` (default `linux/amd64`, the SBOM's platform), `vulnerability-report` with `vulnerability-scanner-uri` and `-version` (a scan already run on the digest, wrapped in the [cosign vulnerability predicate](https://github.com/sigstore/cosign/blob/main/specs/COSIGN_VULN_ATTESTATION_SPEC.md)), `vex-document` (the project's [OpenVEX](https://github.com/openvex/spec) document, checked with `vex.py` as `validate-vex` does; the statements whose product is `pkg:oci/<last segment of subject-name>` are attested for the digest, predicate `https://openvex.dev/ns/v0.2.0`, with the product rewritten to the image's `pkg:oci/<name>@sha256%3A<digest>?repository_url=<subject-name>` and each subcomponent also listed as a product of its own, the form Docker Scout matches; an image no statement names gets none, and an invalid statement fails the job), `base-images-from` (Dockerfiles, one per line: for each `FROM dhi.io/...@sha256:...` base, the statements of the OpenVEX attestation Docker signs for it, checked with the key `supply-chain-policy/base-images.toml` trusts for dhi.io and recorded in the transparency log (an attestation only the key signed is skipped with a warning), that are facts about a package build (`fixed`, or `not_affected` with `vulnerable_code_not_present` or `component_not_present`, and for a package Docker built, `inline_mitigations_already_exist`) are attested too, for each package whose exact build the image holds on every platform: an Alpine package by apk checksum, a Debian package (by binary or source name) by a version only Docker's build carries (`+dhi`, maintainer Docker Hardened Images); a `vex-document` statement wins for the same vulnerability and package; log in to dhi.io first), `on-verified-secret` (`fail` or `record`), `malware-scan` (default `true`), `on-malware` (`fail` or `record`), `attest` (`false` for tests); outputs `sbom-path`, `cyclonedx-path`, `secret-scan-path`, `malware-scan-path`, `vex-path`. Signs, for the digest under its public name: the SBOM in both SPDX 2.3 (`https://spdx.dev/Document/v2.3`) and CycloneDX (`https://cyclonedx.org/bom`) from one syft scan (packages, without package-to-file relationships, which outgrow the 16 MiB attestation limit on a Debian image), a secret scan (trufflehog: counts by verification result and detector, never the secrets or where they are, predicate `https://archestra.ai/attestations/secret-scan/v1`), a malware scan (ClamAV over every file of the image, with signatures fetched for the scan: file counts, the signature database version and each detection's signature and path, predicate `https://archestra.ai/attestations/malware-scan/v1`; skipped with a warning when ClamAV's mirror refuses the download) and, when given, the vulnerability scan and VEX. A secret trufflehog verifies as live, or a ClamAV detection, fails the job before anything is attested. The job needs `id-token: write` and `attestations: write`. syft, trufflehog and oras are pinned by SHA-256 in `install-tools.sh`, the ClamAV image by digest in `malware-scan.sh`; Linux x86_64 runners only. |
| `attest-verification-summary` | `image` (pinned by digest; only the digest is read), `subject-name` | `repository` (default the calling repository), `signer-workflow` (default `attest-provenance.yml` here), `attest` (`false` for tests); output `summary-path`. Verifies the image's build provenance against the [Build Level 3 policy](attest-verification-summary/README.md#policy) and, when it passes, signs a [SLSA verification summary](https://slsa.dev/spec/v1.1/verification_summary) (`https://slsa.dev/verification_summary/v1`) for the digest under its public name. An image with no provenance that meets the policy gets a warning and no summary. The job needs `id-token: write` and `attestations: write`. |
| `previous-release-published` | `tag-prefix` | `mode` (`check` or `recheck`), `release-branches`, `release-workflow`, `token`. Fails a release-please PR while an older release on its line is still a draft and keeps one comment on the PR; `recheck` re-runs the failed checks of open release PRs once they are clear. Callers use the shared caller in its [README](previous-release-published/README.md), so the required check is `Previous Release Published` everywhere. |
| `setup-skopeo` | none | Builds skopeo 1.24.1 from source (Go module checksums verified) and puts it ahead of the runner's skopeo 1.13 on `PATH`. Run it before `skopeo copy --all --preserve-digests` of an image index whose images have zstd layers (every Docker Hardened Images build) or whose descriptors carry `artifactType` (Crossplane packages): 1.13 changes such an index and refuses the copy. |
| `lint-pr-title` | none | `extra-types`: commit types the repository accepts on top of the organization's list (commas, spaces or newlines). Lints the pull request title against the organization's Conventional Commits rules in [`commitlint.config.js`](lint-pr-title/commitlint.config.js); on `merge_group` it passes without linting, so a required check still posts. Needs no checkout and no job permissions. Keep the job name `PR Title Linter` where a ruleset requires that check. |
| `staging-iap` | `gateway-url` on start | Internal Archestra PR reviews only. Opens the existing IAP staging HTTPS tunnel; call again with `operation: stop` in an `always()` step. Requires `id-token: write`. |

Google callers need job permission `id-token: write`. Authentication uses WIF only;
temporary credential cleanup remains enabled. There are no service-account key inputs.
Composite actions preserve the caller's workflow identity, including existing GCP
`job_workflow_ref` trust conditions. [GitHub OIDC reference](https://docs.github.com/actions/deployment/security-hardening-your-deployments/using-openid-connect-with-reusable-workflows).

App tokens retain upstream masking and end-of-job revocation. Preserve each caller's
repository and permission inputs when migrating. An explicit `owner` without
`repositories` grants installation-wide repository scope; avoid that combination.
Omitted permissions retain upstream installation defaults.

Vercel uses CLI `59.15.1`, uploads source and builds remotely. It supports team-scoped
tokens without `vercel pull` or `--prebuilt`. Keep project-specific verification and
smoke tests in the caller. Hosted Ubuntu runners supply Python 3 and Node/npm.

Test locally with `python3 tests/run_python_tests.py actions` (every action's
tests), or name one action directory, for example
`python3 tests/run_python_tests.py actions/vercel-deploy -- -v`.
The Vercel tests use a fake CLI and never authenticate or deploy.
To roll back, revert a caller's pin or its migration PR; no credential rotation is required.
